# Generated level format

Уровень хранится в UTF-8 JSON. `map` содержит `height` строк длиной `width`;
одна клетка равна 12×12 пикселям. В одной клетке находится не более одного символа.

```json
{
  "width": 60,
  "height": 32,
  "style": {
    "profile": "forest",
    "seed": 104729,
    "grass_chance": 0.35
  },
  "star_times": {
    "three_stars": 60,
    "two_stars": 120
  },
  "map": ["..."]
}
```

При загрузке codec разделяет единую карту на внутренние `terrain`, `hazards` и
`entities`.

## Terrain symbols

| Символ | Результат |
| --- | --- |
| `.` | Пустота. |
| `#` | Видимая solid-платформа и `oSolid`. |
| `X` | Тёмная platform-масса без collision. |
| `=` | Jump-through платформа и `oJumpThru`. |

`#` и `X` вместе определяют topology визуальной платформы. Только `#` создаёт
обычную solid-коллизию.

## Hazard symbols

| Символ | Направление и фаза |
| --- | --- |
| `.` | Нет hazard. |
| `^ v < >` | Шипы вверх, вниз, влево, вправо; brush центрирован на клетке. |
| `U D L R` | Те же направления; brush выровнен по границе клетки. |

Brush всегда состоит из четырёх секций по 6 px: наконечник, trap-секция,
solid-секция и основание с `oSolid`. У `^ v < >` клетка покрывает две средние
секции (`6 + 12 + 6`). У `U D L R` направленная граница brush совпадает с
границей клетки (`12 + 12`): `U`/`L` начинаются на ней, `D`/`R` заканчиваются
на ней. Соседние одинаковые символы объединяются в runs; смена фазы начинает
новый run.

Основание каждого шипа должно опираться на `#` или solid/base другого шипа.
Оба внешних края run должны быть окружены `#` или `X` на уровне шипа и ещё
на одну клетку в направлении его основания. Так чёрный низ brush не граничит
с открытым воздухом сбоку.

Соседние по вертикали jump-through runs размещаются с разницей не менее двух
клеток по Y. Разница ровно в две клетки допустима и соответствует высоте прыжка.
Одиночный run обычно примыкает к `#`. Run без боковой опоры допустим только как
часть короткой цепочки, связанной с породой проверенной траекторией прыжка или
безопасного падения.

## Entity symbols

| Символ | Объект |
| --- | --- |
| `@` | Player. |
| `O/o` | Door. |
| `*` | Berry. |
| `S/s` | Slime, runtime scale 0.7–1.0. |
| `K/k` | Skeleton. |
| `B/b` | Bungalo, scale 1.5. |
| `P/p` | Pointer. |

Uppercase создаёт положительный `image_xscale`, lowercase — mirrored. Player и
berry направления не имеют. `@`, `S/s`, `K/k`, `B/b` и `P/p` записываются в
воздушной клетке непосредственно над опорой `#`; runtime-anchor находится на
12 px ниже символа. Door использует координату своей ASCII-клетки и получает
`+6 px` по X. Mini-slime не кодируется в уровне и появляется только при распаде
большого slime с масштабом ровно вдвое меньше родителя.

## Крупные предметы

Необязательный массив `props` хранит вручную размещённые предметы отдельно от
`map`. Процедурный генератор их не расставляет. Пример одной записи:

```json
{
  "id": "prop_1",
  "type": "morning_table",
  "x": 180,
  "y": 336,
  "mirrored": false,
  "opacity": 100,
  "platform_layer": "above",
  "solids": [[-2, -5], [-1, -5], [0, -5], [1, -5]],
  "jump_thrus": [[3, -3], [4, -3]]
}
```

`id` уникален внутри уровня; `type` — slug из
`RandomForest/datafiles/world_props/catalog.json`. Каталог содержит 19 принятых
предметов, исходные размеры, origin и четыре палитры. `x/y` — позиция origin в
игровых пикселях, кратная 6. Масштаб рисунка всегда 1:1.

`solids` содержит сплошные локальные клетки 6×6 px относительно origin.
Необязательный `jump_thrus` хранит такие же клетки для односторонней подложки;
отсутствующее поле означает пустой массив. Без отражения
клетка `[c, r]` начинается в `(x + 6*c, y + 6*r)`, с отражением — в
`(x + 6*(-c-1), y + 6*r)`. Если оба массива пусты, предмет служит фоном без взаимодействия.
Клетки принадлежат предмету: перенос, отражение, дублирование и удаление
затрагивают всю группу. Обычные символы `#` от предметов не зависят.

Каждая строка jump-through-клеток образует отдельную верхнюю поверхность:
игрок проходит снизу, приземляется сверху и спускается клавишей Down, как на
обычной `=`. Подложка невидима; её рисунок уже содержится в спрайте предмета.

Якорь и все клетки обоих типов должны оставаться внутри комнаты. Рисунок может
частично выходить за её границы. Необязательное поле `opacity` задаёт видимость
целым процентом от 0 до 100: 100 — полностью видимый, 0 — невидимый. По умолчанию
100. Необязательное поле `platform_layer` выбирает положение относительно
платформ: `above` (по умолчанию) или `below`. В обоих случаях шипы и персонажи
рисуются впереди предмета. Эти настройки не меняют его коллизии.
Предмет движется без параллакса; палитра выбирается по времени суток уровня.
Коллизии создают невидимые `oSolid` и `oJumpThru`, без платформенных тайлов и травы.
Отсутствие `props` эквивалентно отсутствию предметов; миграция не нужна.

У `light_loom` в общем каталоге задан мягкий источник и затухающий луч.
Игра и редактор учитывают отражение и прозрачность предмета; ночью свет заметнее.
Слой `below` позволяет камню естественно перекрывать и рисунок, и его свет.
Это оформление фонаря, без новых опасностей или вращающихся механизмов.

## Derived content

`style.seed` и координатный hash детерминированно выбирают platform tiles и
grass, не изменяя глобальный RNG GameMaker. `grass_chance` задаёт вероятность
травы на доступных поверхностях без hazard.

`star_times` хранит секундные пороги для трёх и двух звёзд. Одна звезда
выдаётся за любое завершение уровня.

Runtime validator требует ровно одного `@`, одну дверь `O` или `o` и оба
порога `star_times`. Эта проверка намеренно мягче Python validator, который
дополнительно проверяет структуру JSON, геометрию, опоры и доступность объектов.

После ручной правки файл проверяется командой:

```bash
python3 generated_levels/validate_generated_level.py path/to/level.json
```

## Visualizer and editor

Для сохранения изменений запустите из корня репозитория локальный сервер во
встроенном терминале VS Code:

```bash
python3 visualizer/server.py
```

Не закрывая сервер, откройте `visualizer/index.html` и нажмите Preview HTML —
редактор останется внутри VS Code, внешний браузер не нужен. Справа выбирается
режим «Надписи / Карта / Предметы». По умолчанию открыта «Карта»: объекты и блоки,
параметры, затем обозначения. В палитре выбирается символ для вставки.
ЛКМ удаляет содержимое занятой клетки или ставит выбранный
символ в пустую клетку. Клавиша `R`/`К` над клеткой меняет направление сущности
или фазу шипов. Каждое изменение сразу отправляется на запись в JSON выбранного уровня.

Сервер нужен для сохранения во всех режимах. Если он недоступен или запись
не удалась, редактор сохраняет правки в памяти страницы и показывает кнопку
«Повторить сохранение». Автообновление не заменяет несохранённые правки старым
файлом. Можно переключать уровни и возвращаться к черновикам с историей отмены;
после запуска сервера повторное сохранение записывает актуальную версию.
Перезагрузка или закрытие страницы очищает несохранённые черновики.

В режиме **«Предметы»** выберите миниатюру и поставьте рисунок кликом.
Новый экземпляр не имеет коллизий. После размещения можно перетаскивать его
или выбрать через список на панели; шаг переноса — 6 px. У выбранного предмета
можно изменить «Прозрачность, %» и выбрать «Над платформами / Под платформами».
Настройки применяются и сохраняются после изменения поля, поддерживают отмену
и дублируются вместе с предметом. Старые записи без этих полей выглядят как
раньше: 100% и над платформами. Инструмент
**«Коллизии предмета»** работает с выбранным в поле «Тип подложки» вариантом:
Solid или Jump-through. ЛКМ рисует, заменяя другой тип в этой клетке выбранного
предмета; ПКМ стирает только выбранный тип. Другие экземпляры и карта не меняются.
Solid показан квадратом, Jump-through — верхней линией клетки.
Жёлтая подсветка показывает коллизии выбранного предмета, голубая — остальных.
Сетка кисти имеет шаг 6 px. Переключатели рисунков и коллизий помогают видеть
карту под предметами и действуют также в других режимах.

Кнопки дублирования, отражения (`R`/`К`) и удаления (`Delete`) работают со всей
группой. `Esc` возвращает инструмент выбора. Дубликат появляется в той же
позиции и сразу выбран для переноса. Один перенос или мазок кисти отменяется
одним `Ctrl/Cmd+Z`; очередь сохранения и восстановление черновиков общие с
картой и надписями. В режиме карты предметы не перехватывают клики.

## Новые лесные враги

Символы `F/f` (Корневая пасть), `J/j` (смоляной прыгун), `C/c` (коробейник спор), `G/g` (берестяной страж), `W/w` (полый жнец) ставятся в клетку над полом, как существующие наземные враги; `T/t` задаёт воздушную позицию вересковой мыши без сдвига на строку вниз. Строчные символы задают направление влево.

Карта хранит только тип и направление врага. Игра выбирает скин по времени
суток уровня; если нужного скина нет, используется базовый рисунок семейства
(вечерний у прыгуна, ночной у врагов с единственным ночным скином).
Размещать эти типы вручную можно при любом времени суток. Цифры `1–7` больше
не являются символами сущностей. [Параметры и тестовые уровни](forest-enemies.md).
